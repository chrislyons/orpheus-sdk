shmui-juce Components

Introduction

shmui-juce is a production-ready audio visualization library for JUCE applications, ported from ElevenLabs' React/TypeScript shmui component library.

Package Overview

shmui-juce provides battle-tested audio visualization components designed for professional audio applications. Each component is:

  • Thread-safe - AudioAnalyzer works with real-time audio callbacks
  • Production-ready - Used in ElevenLabs' shipping products
  • Customizable - Extensive configuration options
  • Performant - Optimized for smooth 60fps+ rendering

The shmui-juce package includes:

Getting Started

Installation & Setup

shmui-juce is integrated into the Orpheus SDK as packages/shmui-juce/. To use it in your application:

1. Include the Header

// Include all shmui components via main header
#include <ShmUI.h>

2. Create Components

// Audio analysis (on message thread)
auto analyzer = std::make_unique<shmui::AudioAnalyzer>();

// Visualizer (on message thread)
auto visualizer = std::make_unique<shmui::BarVisualizer>();
visualizer->setAudioAnalyzer(analyzer.get());
visualizer->setBarCount(12);

3. Feed Audio Data

// In your audio callback (audio thread)
void processAudio(juce::AudioBuffer<float>& buffer) {
  analyzer->processBlock(buffer);  // Thread-safe!
}

Design Token Integration

Integrate with your design system using design tokens:

// Using OCC design tokens
#include "UI/DesignTokens.h"

visualizer->setBarColour(juce::Colour(OCC::Design::kAccentCyan));
visualizer->setBackgroundColour(juce::Colour(OCC::Design::kBgPrimary));
💡 Best Practice

Always use a centralized color system (design tokens) for UI consistency. See Integration Patterns for complete examples.

Threading Model Overview

Critical for real-time audio safety:

  • AudioAnalyzer - ✅ Lock-free, safe for audio thread
  • All visualizers - Message thread only (JUCE components)
  • Communication - Use atomic operations internally, no locks

Never call visualizer methods from the audio thread. Use juce::MessageManager::callAsync() for cross-thread updates.

AudioAnalyzer

Foundation component for all audio visualization. Performs thread-safe FFT analysis, RMS calculation, and frequency band splitting.

Purpose

AudioAnalyzer is the core audio processing engine. It:

  • Performs FFT (Fast Fourier Transform) analysis on audio data
  • Calculates RMS (root mean square) and peak levels
  • Splits frequency spectrum into configurable bands
  • Provides thread-safe lock-free communication between audio and UI threads
✅ Thread-Safe

AudioAnalyzer uses lock-free atomic operations internally. It's safe to call processBlock() from the audio thread and read from the message thread simultaneously.

Key Features

Feature Description
FFT Modes Waveform (256-sample) and Spectrum (2048-sample)
Frequency Bands Configurable number of bands with smoothing
RMS/Peak Levels 0.0-1.0 normalized with -100dB to -10dB range
Voice-Focused Range 5%-40% of frequency bins (optimized for speech)
dB Normalization Automatic gain staging for consistent levels

API Reference

Method Thread Description
processBlock() Audio Process audio buffer (real-time safe)
getFrequencyData() UI Get raw FFT frequency data
getFrequencyBands() UI Get averaged frequency bands
getRMSLevel() UI Get RMS level (0.0-1.0)
getPeakLevel() UI Get peak level (0.0-1.0)
setSmoothingTimeConstant() UI Set smoothing factor (0.0-1.0)
setSensitivity() UI Set sensitivity multiplier

Configuration Options

Option Default Range Effect
Smoothing Time Constant 0.8 0.0-1.0 Higher = smoother but slower response
Sensitivity 1.0 0.1-10.0 Multiplier for amplitude scaling
Analysis Mode Spectrum Waveform/Spectrum FFT window size (256 vs 2048)

Code Example: Basic Setup

class MyAudioComponent : public juce::AudioAppComponent {
private:
  std::unique_ptr<shmui::AudioAnalyzer> m_analyzer;

public:
  MyAudioComponent() {
    m_analyzer = std::make_unique<shmui::AudioAnalyzer>();
    setAudioChannels(2, 2);
  }

  void audioDeviceIOCallback(const float** inputChannelData,
                                int numInputChannels,
                                float** outputChannelData,
                                int numOutputChannels,
                                int numSamples) override {
    // Process input audio
    juce::AudioBuffer<float> buffer(const_cast<float**>(inputChannelData),
                                        numInputChannels,
                                        numSamples);

    // Feed to analyzer (thread-safe!)
    m_analyzer->processBlock(buffer);

    // Output passthrough
    for (int ch = 0; ch < numOutputChannels; ++ch) {
      std::copy(inputChannelData[ch],
                inputChannelData[ch] + numSamples,
                outputChannelData[ch]);
    }
  }
};

Code Example: Reading Analysis Data

// On message thread (e.g., in paint() or timer callback)
std::vector<float> bands;
m_analyzer->getFrequencyBands(bands, 12, 100, 8000);

float rmsLevel = m_analyzer->getRMSLevel();  // 0.0-1.0
float peakLevel = m_analyzer->getPeakLevel();  // 0.0-1.0

// Use levels for visualization
for (int i = 0; i < bands.size(); ++i) {
  float bandHeight = bands[i] * 100;  // Scale to 0-100px
  drawVisualizerBar(i, bandHeight);
}
⚠️ Threading Requirements

Call processBlock() only from the audio thread. Call getters (like getRMSLevel()) only from the message thread. Never call visualizer methods from the audio thread.

Performance Notes

  • CPU: ~2-3% on modern CPUs (2048-sample FFT)
  • Latency: ~10-20ms (one buffer of analysis delay)
  • Memory: ~100KB per instance (FFT buffers)
  • No allocations: All memory pre-allocated on construction

BarVisualizer

Multi-band frequency display with smooth animations and agent state support. Perfect for real-time audio feedback and voice assistant UI.

Purpose

BarVisualizer displays frequency bands as vertical bars with smooth animations. It's designed for:

  • Real-time audio level visualization (VU meter replacement)
  • Voice assistant UI (Listening, Thinking, Speaking states)
  • Frequency spectrum analysis feedback
  • Visual confirmation of audio activity

Key Features

Feature Description
Configurable Bars 1-32 frequency bands (default: 15)
Agent States Idle, Listening, Thinking, Speaking
Height Range Percentage-based min/max scaling
Alignment Center or bottom-aligned bars
Demo Mode Animated bars without audio input
Smooth Animation Exponential smoothing with 60fps+ support

API Reference

Method Description
setBarCount(int) Number of frequency bands (1-32)
setHeightRange(float min, float max) Min/max bar height as percentage (0-100)
setAudioAnalyzer() Connect AudioAnalyzer for FFT data
setAgentState() Set animation state (Idle/Listening/Thinking/Speaking)
setDemoMode(bool) Enable fake animated data (for testing)
setCenterAlign(bool) Center bars from middle vs bottom-align
setVolumeBands() Manually set band heights (0.0-1.0)

Appearance Configuration

Method Description
setBarColour() Active bar color (e.g., cyan)
setHighlightColour() Highlight during state animations
setBackgroundColour() Background fill color

Agent States

BarVisualizer supports different animation patterns for voice assistant states:

State Animation Use Case
Idle Static (no animation) No activity
Listening Responsive bars to input Waiting for user input
Thinking Pulsing highlight Processing input
Speaking Animated bars to output Playing response

// In MainComponent constructor
m_barVisualizer = std::make_unique<shmui::BarVisualizer>();

m_barVisualizer->setBarColour(juce::Colour(0xFF00FFFF));  // Cyan

m_barVisualizer->setHeightRange(10.0f, 100.0f);  // 10-100px

// Connect to audio analyzer
if (m_audioEngine && m_audioEngine->getAudioAnalyzer()) {
  m_barVisualizer->setAudioAnalyzer(m_audioEngine->getAudioAnalyzer());
}

// Respond to user interactions with animations

// Load audio file and extract waveform data
std::vector<float> waveformData = extractWaveformFromFile("audio.wav");

// Create visualizer with custom style
auto waveform = std::make_unique<shmui::WaveformVisualizer>();

shmui::WaveformStyle style;
style.barWidth = 6.0f;
style.barGap = 3.0f;

style.alphaMin = 0.2f;

waveform->setStyle(style);
waveform->setData(waveformData);

// Optional: handle clicks
waveform->onBarClick = [this](int index, float value) {

addAndMakeVisible(waveform.get());

Visual Characteristics

  • Responsive: Scales to component bounds automatically
  • Edge fade: Gradient transparency at left/right edges for focus
  • Alpha mapping: Opacity varies with amplitude (soft → loud = transparent → opaque)
  • Efficient rendering: Cached bar positions, minimal redraws

Threading Safety Guide

Critical knowledge for working with shmui in real-time audio applications.

Thread-Safe: AudioAnalyzer Only

AudioAnalyzer uses lock-free atomic operations and is safe to call from the audio thread:

Method Safe Thread Notes
processBlock() Audio thread No locks, no allocations
getRMSLevel() Either (atomic read) Lock-free atomic read from UI thread safe
getFrequencyBands() UI thread Copies atomic data to output vector

Message Thread Only: All Visualizers

All visualizer components (BarVisualizer, WaveformVisualizer, etc.) are JUCE Components and must be created/configured/destroyed on the message thread:

Component Thread Model Why
BarVisualizer Message thread Inherits from juce::Component
WaveformVisualizer Message thread UI rendering, event handling
MatrixDisplay Message thread Animation timer, JUCE component
OrbVisualizer Message thread OpenGL context (main thread only)

Cross-Thread Communication Pattern

Use juce::MessageManager::callAsync() to safely communicate between threads:

// IN AUDIO THREAD: Push event to message thread
juce::MessageManager::callAsync([this]() {
  m_visualizer->setAgentState(shmui::BarVisualizer::AgentState::Speaking);
});

// OR: IN AUDIO THREAD: Update via atomic if component supports it
// (Usually not recommended for components)

Common Pitfalls

❌ Mistake #1: Calling visualizer from audio thread
// WRONG! Don't do this:
void audioCallback(...) {
  m_visualizer->paint(...);  // ← CRASH! Can't render from audio thread
  m_visualizer->setBarCount(12);  // ← WRONG! Not thread-safe
}

// RIGHT! Use message thread:
void audioCallback(...) {
  m_analyzer->processBlock(buffer);  // ✅ OK (AudioAnalyzer only)

  // Schedule visualizer update for message thread
  juce::MessageManager::callAsync([this]() {
    m_visualizer->setBarCount(12);  // ✅ OK
  });
}
❌ Mistake #2: Blocking audio thread
// WRONG! Blocks audio thread:
void audioCallback(...) {
  std::lock_guard<std::mutex> lock(m_analyzerMutex);  // ← GLITCH! Blocks audio
  m_analyzer->processBlock(buffer);
}

// RIGHT! Use lock-free primitives:
void audioCallback(...) {
  m_analyzer->processBlock(buffer);  // ✅ No locks needed
}
❌ Mistake #3: Allocating from audio thread
// WRONG! Dynamic allocation:
void audioCallback(...) {
  std::vector<float> bands;  // ← CRASH! Can allocate
  m_analyzer->getFrequencyBands(bands, 12);
}

// RIGHT! Pre-allocate or read atomically:
private:
  std::vector<float> m_bands{12};  // Pre-allocated

void onMessageThread() {
  m_analyzer->getFrequencyBands(m_bands, 12);  // ✅ UI thread
}

float getAudioLevelFromAudioThread() {
  return m_analyzer->getRMSLevel();  // ✅ Atomic read
}

Safe Usage Checklist

  • ✅ Call AudioAnalyzer::processBlock() from audio thread
  • ✅ Call visualizer methods from message thread
  • ✅ Use juce::MessageManager::callAsync() for cross-thread updates
  • ✅ Pre-allocate all memory before audio thread starts
  • ✅ No locks or waits on audio thread
  • ✅ No I/O operations on audio thread
  • ✅ Read level data atomically if needed from audio thread
  • ❌ Never call visualizer methods from audio thread
  • ❌ Never allocate memory on audio thread
  • ❌ Never use std::mutex on audio thread

Integration Patterns

Proven patterns for integrating shmui components into your Orpheus-based applications.

Pattern 1: Basic Audio Visualization

Simple setup with AudioAnalyzer + BarVisualizer:

// Header file
class MainComponent : public juce::Component {
private:
  std::unique_ptr<shmui::AudioAnalyzer> m_analyzer;
  std::unique_ptr<shmui::BarVisualizer> m_visualizer;
};

// Implementation
MainComponent::MainComponent() {
  m_analyzer = std::make_unique<shmui::AudioAnalyzer>();
  m_visualizer = std::make_unique<shmui::BarVisualizer>();
  m_visualizer->setAudioAnalyzer(m_analyzer.get());
  m_visualizer->setBarCount(12);
  addAndMakeVisible(m_visualizer.get());
}

// Audio callback
void processAudio(juce::AudioBuffer<float>& buffer) {
  m_analyzer->processBlock(buffer);  // Thread-safe!
}

Pattern 2: Design Token Integration

Consistent styling with design tokens:

#include "UI/DesignTokens.h"

setupVisualizer() {
  // Use design tokens for colors
  m_visualizer->setBarColour(
    juce::Colour(OCC::Design::kAccentCyan)
  );
  m_visualizer->setBackgroundColour(
    juce::Colour(OCC::Design::kBgPrimary)
  );

  // All components now match design system
}

Pattern 3: Demo Mode for Testing

Test visualizations without audio input:

// Enable fake animated data for UI preview
m_visualizer->setDemoMode(true);  // Animate fake data

// No analyzer connection needed
// Component generates smooth animated bars

Pattern 4: Real-World Example (Clip Composer)

From MainComponent.cpp:

void MainComponent::resized() {
  // Layout: Clip grid on left, visualizer on right

When to Use Each Component

💡 Choosing the Right Component
  • Real-time audio feedback? → BarVisualizer or LiveWaveform
  • Show pre-recorded audio? → WaveformVisualizer or AudioScrubber
  • Decorative/loading animation? → ScrollingWaveform or MatrixDisplay
  • Premium 3D effect? → OrbVisualizer (requires OpenGL)
  • Voice assistant UI? → BarVisualizer with agent states
  • Custom layout? → AudioAnalyzer + custom component

OpenGL Requirements

Only OrbVisualizer requires OpenGL:

  • OpenGL 2.0+ required
  • JUCE automatically manages context
  • All other components work on software rendering
